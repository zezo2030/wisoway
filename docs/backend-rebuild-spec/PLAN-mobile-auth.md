# خطة التنفيذ — التسجيل وتسجيل الدخول في تطبيق الموبايل (Flutter)

> **الغرض:** خطة قابلة للتنفيذ لإعادة بناء طبقة المصادقة في تطبيق الموبايل — الشاشات،
> إدارة الحالة، تخزين التوكنات، اعتراض الطلبات، بصمة الجهاز، والتعامل مع الأخطاء.
>
> مستخرجة من `rideshare/lib` على فرع `009-platform-refinements`، وكل ادعاء متحقق منه
> من الكود مع `file:line`.
>
> **الوثيقة المقابلة في الخلفية:** [`PLAN-auth-signup-and-sms.md`](PLAN-auth-signup-and-sms.md) —
> اقرأها أولاً؛ هذه الوثيقة تفترض معرفة عقود الـ API الموصوفة هناك.

## 1. 🔴 مشاكل حرجة يجب حسمها قبل البدء

هذه ليست تفاصيل تنفيذ — هي أعطال متتبَّعة من طرف لطرف.

### 1.1 عنوان الخادم مثبّت على IP محلي عبر HTTP

```dart
// core/api/api_endpoints.dart:3
static const String baseUrl = 'http://192.168.1.9/api/v1';
// static const String baseUrl = 'https://vision-way.tech/api/v1';   ← معطّل
```

عنوان LAN مثبّت في الكود المرفوع، وعنوان الإنتاج **معطّل بتعليق**. والأخطر أن البروتوكول
`http` وليس `https` — **كلمات المرور والتوكنات تنتقل بنص صريح**.

**الإصلاح:** اجعله مشتقاً من البيئة (`--dart-define`) مع فرض HTTPS في الإنتاج، وفعّل
`ATS` على iOS و `cleartextTrafficPermitted=false` على Android.

### 1.2 شاشة الحظر لا تظهر أبداً — عطل متتبَّع بالكامل

تتبّعت المسار من الحارس إلى الشاشة:

**الخطوة 1** — `BanGuard` يرمي الاستثناء الصحيح:
```ts
throw new ForbiddenException({
  code: 'ACCOUNT_BANNED', banReason, supportWhatsApp
});
```

**الخطوة 2** — `HttpExceptionFilter` **يُسقط الحمولة بالكامل**. الكائن المُمرَّر لا يحوي
مفتاح `message`، و`getErrorDetails` يبحث عن `error.details` أو `message` فقط → يُعيد `null`.
الجسم الفعلي الذي يصل للتطبيق:

```json
{ "success": false,
  "error": { "code": 403, "message": "Forbidden", "details": null,
             "timestamp": "...", "path": "...", "method": "..." } }
```

`ACCOUNT_BANNED` و `banReason` و `supportWhatsApp` **اختفت كلها**.

**الخطوة 3** — التطبيق يقرأ من المكان الخطأ أصلاً:
```dart
// core/api/auth_interceptor.dart:47-48
final code = data is Map ? data['code'] as String? : null;   // ← null دائماً
if (code == 'ACCOUNT_BANNED') { ... }                        // ← لا يتحقق أبداً
```
حتى لو وصل الكود، فهو تحت `data['error']['code']` وليس `data['code']`، وقيمته `403` رقماً
وليس نصاً.

**النتيجة:** `banned_screen.dart` (195 سطر) **كود ميت لا يُعرض إطلاقاً**. المستخدم المحظور
يرى خطأ 403 عاماً.

**الإصلاح يتطلب الطرفين:** عدّل الـ filter ليحافظ على الحقول المخصصة، وعدّل التطبيق ليقرأ
`data['error']['code']`.

### 1.3 ابتلاع الأخطاء يخفي السبب الحقيقي

```dart
// core/services/auth_service.dart:78-81
try { await _api.post(ApiEndpoints.sendOtp, ...); }
catch (e) { throw Exception('فشل إرسال كود التحقق. الرجاء المحاولة مرة أخرى.'); }
```
```dart
// core/services/auth_service.dart:141-143
catch (e) { throw Exception('كود التحقق غير صحيح أو منتهي الصلاحية'); }
```

كل استثناء يُستبدل برسالة عربية واحدة. النتائج الملموسة:

| ما حدث فعلاً | ما يراه المستخدم | الصواب |
|---|---|---|
| `409` الحساب مسجَّل — استخدم الباسورد | «كود التحقق غير صحيح» | وجّهه لشاشة الدخول |
| `400` الباسورد مطلوب لإكمال الإعداد | «كود التحقق غير صحيح» | اطلب الباسورد |
| `401` الجهاز ملغى | «كود التحقق غير صحيح» | اعرض رسالة الجهاز الملغى |
| `429` تجاوز حد الطلبات | «فشل إرسال كود التحقق» | اعرض مهلة الانتظار |
| `400` Twilio غير مضبوط | «فشل إرسال كود التحقق» | خطأ خادم، سجّله |
| انقطاع الشبكة | «فشل إرسال كود التحقق» | «تحقق من اتصالك» |

> **الحالة الأولى هي الأسوأ:** المستخدم لديه كود صحيح تماماً ويُقال له إنه خاطئ، بلا أي
> طريق للأمام. هذا يوقف المستخدم العائد عن الدخول نهائياً.

**الإصلاح:** أنشئ `AuthException` تحمل `statusCode` و `errorCode`، ومرّرها للواجهة لتفرّع
عليها. راجع §5.

### 1.4 كلمة المرور تُخزَّن بنص صريح على الجهاز

`PendingDriverRegistration` (`models/pending_driver_registration.dart:20`) يحمل حقل
`password` نصاً صريحاً، ويُسلسَل في `toJson()` (السطر 43) ويُكتب في التخزين الآمن تحت
`pending_driver_registration`.

```dart
final String password;                       // :20
Map<String, dynamic> toJson() => {
  ...
  'password': password,                      // :43   ← نص صريح
};
```

السبب أن معالج التسجيل يجمع الباسورد في الخطوة 1 ولا يستخدمه إلا في النداء الأخير، فيُحفظ
بينهما ليسمح بالاستئناف بعد إغلاق التطبيق.

**الخطورة:** التخزين الآمن يحمي من التطبيقات الأخرى، لكنه **لا يحمي من جهاز مكسور الحماية
(root/jailbreak) ولا من نسخة احتياطية غير مشفّرة**. الباسورد يبقى مخزّناً طوال مدة
المعالج — وإن هجره المستخدم يبقى حتى انتهاء صلاحية التوكن (30 دقيقة) ثم يُمسح عند التشغيل التالي.

**الإصلاح:** لا تخزّن الباسورد إطلاقاً. اطلبه في **الخطوة الأخيرة** مباشرة قبل نداء
`register`، أو أرسله في `driver/verify-phone` ودع الخادم يحمله داخل توكن التسجيل الموقَّع.

### 1.5 بيانات دخول الأدمن مرفوعة في المستودع

```dart
// main.dart:74-75
//admin@rideshare.com
//Admin@123456
```

تعليق مرفوع في المستودع يحمل بريد الأدمن وكلمة مروره. وهما **بالضبط القيمتان
الافتراضيتان في `seed-admin.ts`** بالخلفية (`ADMIN_EMAIL` / `ADMIN_PASSWORD`).

**الخطورة مركّبة:** إن كان النظام المنشور ما زال يستخدم القيم المزروعة الافتراضية، فأي
شخص لديه وصول للمستودع **يملك دخولاً إدارياً كاملاً مباشرة** — بلا حاجة حتى لثغرة ترقية
الصلاحيات المذكورة في خطة الخلفية §9b #0.

**الإصلاح فوراً:**
1. احذف السطرين من الكود.
2. **غيّر كلمة مرور الأدمن في الإنتاج** — اعتبرها مكشوفة.
3. امسحها من تاريخ Git إن كان المستودع سيُشارَك.
4. اجعل `ADMIN_PASSWORD` إلزامياً بلا قيمة افتراضية في سكربت الزرع.

### 1.6 ثلاثة تحققات مختلفة لرقم الهاتف — ولا واحد منها E.164

| الموضع | القاعدة |
|---|---|
| `widgets/auth/auth_phone_field.dart:119` | `^0?\d{7,15}$` |
| `screens/auth/forgot_password_screen.dart:223` | `^\d{7,15}$` |
| `screens/auth/phone_auth_screen.dart:166` | `formattedPhone.length < 10` |

**الخادم يفرض `^\+[1-9]\d{1,14}$`** — أي E.164 كاملة برمز الدولة.

نتيجتان:
1. **عدم اتساق داخلي:** رقم يبدأ بصفر يمرّ من الودجت ويُرفض في شاشة نسيان كلمة المرور.
2. **التحقق لا يطابق العقد** — الشاشات تتحقق من الجزء المحلي فقط، ورمز الدولة يُضاف
   لاحقاً. أي خلل في الإضافة ينتج رقماً يرفضه الخادم بعد أن أجازته الواجهة.

> بلاغ مؤكَّد: `forgot_password_screen.dart` **يضاعف بادئة رمز الاتصال** إن كتب المستخدم
> `+` بنفسه.

**الإصلاح:** دالة تطبيع واحدة مشتركة تُنتج E.164 وتتحقق منها بنفس تعبير الخادم، تُستخدم في
كل شاشة بلا استثناء.

### 1.7 تجديد التوكن بلا قفل — سباق

`AuthInterceptor.onError` (السطر 66) يُجدّد التوكن عند كل 401 **بلا mutex ولا طابور**.
عند تحميل شاشة تُطلق عدة طلبات متزامنة وتنتهي صلاحية التوكن، كل طلب يبدأ تجديداً منفصلاً.

مع **تدوير التوكنات** (المطلوب إضافته في الخلفية — راجع خطة الخلفية §7.2) يصبح هذا كارثياً:
أول تجديد ينجح ويُبطل التوكن القديم، والبقية تفشل وتمسح الجلسة.

**الإصلاح:** قفل واحد + طابور؛ الطلب الأول يُجدّد والبقية تنتظر نتيجته.

### 1.8 فشل التجديد يمسح الجلسة بصمت

```dart
// auth_interceptor.dart:92-94
catch (e) { await _tokenStorage.clearAll(); }
```
تُمسح التوكنات لكن **لا انتقال لشاشة الدخول ولا إشعار**. المستخدم يبقى في شاشة تفشل
طلباتها بلا تفسير.

**الإصلاح:** أطلق حدث «انتهت الجلسة» ينتقل لشاشة الدخول ويعرض رسالة.

## 2. تخزين التوكنات

### 2.1 الوضع الحالي — `core/storage/token_storage.dart`

Singleton فوق `FlutterSecureStorage` بأربعة مفاتيح:

| المفتاح | المحتوى |
|---|---|
| `access_token` | توكن الوصول (صلاحية 15 دقيقة) |
| `refresh_token` | توكن التجديد (صلاحية 7 أيام) |
| `user_id` | معرّف المستخدم |
| `pending_driver_registration` | حالة تسجيل السائق غير المكتمل (JSON) |

بالإضافة إلى `device_install_salt` المكتوب مباشرة من `DeviceFingerprintService`.

`hasTokens()` يفحص **وجود** توكن الوصول فقط — لا يفحص انتهاء صلاحيته.

### 2.2 ⚠️ تعارض السلوك بين المنصّتين

`flutter_secure_storage` يستخدم **Keychain** على iOS و **EncryptedSharedPreferences**
على Android. الفرق الجوهري:

| | Android | iOS |
|---|---|---|
| بعد إلغاء تثبيت التطبيق | ❌ يُمسح | ✅ **يبقى في الـ Keychain** |

الأثر على `device_install_salt`:
- **Android:** إعادة التثبيت تولّد ملحاً جديداً → بصمة جديدة → صف جهاز جديد → **يزيد عدّاد
  تعدد الحسابات لكل جهاز** وقد يؤدي لتقييد تلقائي خاطئ.
- **iOS:** الملح يبقى → البصمة ثابتة عبر إعادة التثبيت.

> تعليق الملف نفسه متناقض: الترويسة تقول «across app reinstalls where possible» بينما
> توثيق الدالة يقول «reset on a full reinstall». السلوك الفعلي يعتمد على المنصّة.

**الإصلاح:** اضبط `IOSOptions(accessibility: first_unlock_this_device)` واحذف الملح صراحة
عند أول تشغيل بعد تثبيت جديد (اكشفه بعَلَم في `SharedPreferences` العادية التي تُمسح مع
إلغاء التثبيت على المنصّتين).

### 2.3 ما يجب فعله في إعادة البناء

- [ ] خزّن **وقت انتهاء صلاحية** التوكن بجانبه، وجدّد **استباقياً** قبل انتهائه بدل انتظار 401
- [ ] `hasValidSession()` تفحص الصلاحية لا الوجود فقط
- [ ] وحّد سلوك الملح بين المنصّتين
- [ ] لا تخزّن `user_id` منفصلاً — استخرجه من `sub` في التوكن

## 3. بصمة الجهاز

### 3.1 الخوارزمية

التطبيق يجمع الحمولة، والخادم يحسب التجزئة:

```
العميل يرسل:  { deviceId, installSalt, platform, fcmToken?, locale?, isMockLocation }
الخادم يحسب:  SHA256( platform + ":" + deviceId + ":" + installSalt )
```

| الحقل | المصدر |
|---|---|
| `deviceId` | Android: `androidInfo.id` · iOS: `iosInfo.identifierForVendor` · احتياطي: `'unknown-device'` |
| `installSalt` | UUID v4 بلا شرطات، مخزّن في `flutter_secure_storage` |
| `platform` | `'ios'` أو `'android'` |
| `locale` | `Platform.localeName.split('_').first` → مثل `"ar"` |
| `isMockLocation` | ثابت `false` دائماً |

> `deviceId` الخام **لا يُخزَّن على الخادم** — يُستخدم للتجزئة فقط. تصميم جيد، حافظ عليه.

### 3.2 ملاحظات

- الاحتياطي `'unknown-device'` عند فشل قراءة معلومات الجهاز يعني أن **كل الأجهزة الفاشلة
  تتشارك البصمة نفسها** (لأن الملح يختلف فعلياً، فالخطر محدود — لكن يستحق تسجيلاً في اللوج).
- `isMockLocation` يُرسل دائماً `false` — والخادم **يتجاهله تماماً** في `verify-otp`. حقل ميت
  على الطرفين.
- **`signIn` لا يبني حمولة جهاز إطلاقاً** (راجع §4.3) — فجوة أمنية.

## 4. المسارات الثلاثة

### 4.1 مسار الراكب — إنشاء حساب / تحقق

```
   welcome_screen
        │
        ▼
   account_type_selection  ──(سائق)──►  مسار السائق (§4.2)
        │ (راكب)
        ▼
   phone_auth_screen          POST /auth/send-otp   { phoneNumber }
        │
        ▼
   otp_verification_screen    POST /auth/verify-otp { phoneNumber, code,
        │                                             name?, gender?, role?,
        │                                             password?, device }
        ▼
   profile_setup_screen  (عند الحاجة)
        │
        ▼
   الشاشة الرئيسية
```

**بناء الحمولة** (`auth_service.dart:88-108`) — الحقول الاختيارية تُضاف فقط عند وجودها
وكونها غير فارغة:
```dart
body = { 'phoneNumber': ..., 'code': code.trim() };
if (device != null)                     body['device']   = device.toJson();
if (name != null && name.trim().isNotEmpty) body['name'] = name.trim();
if (gender != null && gender.isNotEmpty)    body['gender'] = gender;
if (role != null && role.isNotEmpty)        body['role']   = role;
if (password != null && password.isNotEmpty) body['password'] = password;
```

**تسلسل `AuthProvider.verifyOTP`** (`auth_provider.dart:135-183`):
1. تهيئة `PushNotificationService` وجلب توكن FCM — **داخل `try/catch` صامت**، الفشل لا يوقف المصادقة ✅
2. بناء حمولة الجهاز مع توكن FCM
3. نداء `AuthService.verifyOTP`
4. حفظ `accountState` و `deviceState` و `pendingPhoneLinkRequired`
5. تسجيل توكن الجهاز للإشعارات

**معالجة الاستجابة** (`auth_service.dart:112-140`) — فرعان:
- `accessToken != null` → احفظ التوكنات ومعرّف المستخدم، حدّث `_currentUser`
- `accessToken == null` → اعتبرها ربط هاتف فقط، أعد جلب الملف الشخصي

> ⚠️ `data['user']['_id'] ?? data['user']['id']` — بقايا من عصر MongoDB. الخادم يُعيد `id`
> فقط. احذف `_id` في إعادة البناء.

### 4.2 مسار السائق

ثلاث خطوات مؤجلة — لا يُحفظ شيء حتى تنجح الخطوة الأخيرة:

```
   POST /auth/driver/verify-phone  { phoneNumber, code }
        └─► { registrationToken, expiresIn: 1800 }
        └─► يُحفظ في pending_driver_registration (secure storage) ✅
   POST /uploads/registration      multipart { file, registrationToken }
        └─► { url }   × عدد المستندات
   POST /auth/driver/register      { registrationToken, name, password,
                                     vehicleType, plateNumber, model, seats,
                                     carImageUrl, insuranceImageUrl, ... }
        └─► AuthResponse → حفظ التوكنات
```

**نقطة جيدة:** توكن التسجيل يُحفظ في التخزين الآمن تحت `pending_driver_registration`
(`auth_provider.dart:87 _loadPendingDriverRegistration`)، فالمسار **يُستأنف بعد إعادة تشغيل
التطبيق**. حافظ على هذا.

**نقطة تحتاج انتباهاً:** التوكن صالح **30 دقيقة فقط**. راجع §6 لمعالجة الانتهاء.

`registerDriver` في التطبيق (`auth_service.dart:190-214`) يجعل `seats` و `carImageUrl` و
`insuranceImageUrl` **مطلوبة على مستوى دالة Dart** — متوافق مع الخادم. ✅

> `seats` تُرسل دائماً صراحة، وهي **تتغلّب على القيمة المشتقّة من كتالوج أنواع المركبات**
> في الخادم. تأكد أن ما يرسله التطبيق يطابق تخطيط المقاعد الفعلي وإلا تباعدت القيمتان.

### 4.3 تسجيل الدخول

```dart
// auth_service.dart:54-69
POST /auth/login  { phoneNumber, password }
```

هاتف + كلمة مرور فقط. لا فرع إيميل (وهو للأدمن حصراً في الخادم — صحيح).

> 🔴 **`signIn` لا يرسل كتلة `device`** (`auth_service.dart:57-60`، و
> `auth_provider.dart:454-472` لا يبني حمولة جهاز). النتيجتان:
> 1. التوكن يحمل `did: null` → **ينجو من إلغاء الجهاز**. من يُلغِ جهازه ثم يدخل بالباسورد
>    يستعيد الوصول كاملاً.
> 2. `_accountState` و `_deviceState` **لا تُحدَّثان عند الدخول** — تبقيان على قيمتيهما
>    السابقتين. المستخدم المحظور الداخل بالباسورد لا يُعرَف حظره حتى الطلب التالي.
>
> **الإصلاح:** ابنِ حمولة الجهاز وأرسلها في `login` أيضاً، وحدّث حالتَي الحساب والجهاز
> من الاستجابة.

### 4.4 تسجيل الخروج

```dart
// auth_provider.dart:649-662  →  auth_service.dart:380-389
_deregisterDeviceToken();          // إلغاء تسجيل FCM
_api.post(ApiEndpoints.logout);    // إبلاغ الخادم (يُتجاهل فشله)
_tokenStorage.clearAll();          // مسح محلي — في finally ✅
```

المسح المحلي في `finally` فيبقى صحيحاً حتى لو فشل نداء الخادم. ✅

> ⚠️ لكن **الخادم لا يُبطل أي توكن** (راجع خطة الخلفية §7.2). التوكنات المسروقة تبقى صالحة
> حتى 7 أيام بعد «الخروج». الإصلاح في الخلفية لا في التطبيق.
>
> ⚠️ `clearAll()` يمسح **كل** التخزين الآمن بما فيه `device_install_salt` → البصمة تتغيّر بعد
> كل تسجيل خروج → صف جهاز جديد في كل مرة → **تضخيم عدّاد تعدد الحسابات**. امسح مفاتيح
> الجلسة انتقائياً بدل `deleteAll()`.

## 5. معالجة الأخطاء — التصميم المطلوب

هذا أكبر فرق بين الوضع الحالي والمطلوب.

### 5.1 نوع خطأ محدّد

```dart
class AuthException implements Exception {
  final int? statusCode;      // 400, 401, 409, 429 ...
  final String? errorCode;    // 'ACCOUNT_BANNED', 'SEATS_TAKEN' ...
  final String message;       // رسالة جاهزة للعرض (مترجمة)
  final AuthFailure kind;     // تصنيف يُفرَّع عليه
}

enum AuthFailure {
  invalidOtp, otpExpired, alreadyRegistered, passwordRequired,
  deviceRevoked, accountBanned, accountRestricted, rateLimited,
  network, server, unknown,
}
```

### 5.2 جدول التخطيط

| الحالة | كود الخادم | `AuthFailure` | سلوك الواجهة |
|---|---|---|---|
| كود خاطئ | 401 `Invalid or expired OTP code` | `invalidOtp` | خطأ سطري تحت خانات الكود + مسحها |
| **الحساب مسجَّل** | **409** | `alreadyRegistered` | **انتقل لشاشة الدخول مع تعبئة الهاتف مسبقاً** |
| الباسورد مطلوب | 400 `Password is required…` | `passwordRequired` | اعرض حقل الباسورد في نفس الشاشة |
| الجهاز ملغى | 401 `This device has been revoked` | `deviceRevoked` | حوار «جهاز غير موثوق» + رابط الدعم |
| محظور | 403 `ACCOUNT_BANNED` | `accountBanned` | `banned_screen` بالسبب ورقم الدعم |
| مقيّد | — (في `accountState`) | `accountRestricted` | شريط تحذيري دائم |
| تجاوز الحد | 429 | `rateLimited` | عدّاد تنازلي + تعطيل الزر |
| الشبكة | `DioExceptionType.connection*` | `network` | «تحقق من اتصالك» + إعادة محاولة |

### 5.3 قواعد

1. **لا تبتلع الاستثناء أبداً.** حوّله لنوع محدّد واحتفظ بالأصل للتسجيل.
2. **الرسائل من ملفات الترجمة**، لا نصوص عربية مثبّتة في `auth_service.dart` كما هي الآن.
3. **فرّق بين خطأ المستخدم وخطأ النظام** — الأول يُعرض، والثاني يُسجَّل ويُعرض بشكل عام.

## 6. دورة حياة توكن تسجيل السائق

التوكن صالح **1800 ثانية (30 دقيقة)**، والمستخدم يقضي أغلبها في تصوير المستندات ورفعها.

### 6.1 الموجود فعلاً — أفضل مما يبدو

الأساس مبنيّ بشكل صحيح، خلافاً لما قد يُتوقَّع:

| الآلية | الموضع | الحالة |
|---|---|---|
| حساب وقت الانتهاء وحفظه | `pending_driver_registration.dart:13` (`expiresAtEpochMs`) | ✅ |
| فاحص الصلاحية | نفس الملف:32 (`isExpired`) | ✅ |
| مسح السجل المنتهي عند الإقلاع | `auth_provider.dart:90-92` | ✅ |
| فحص قبل نداء التسجيل | `auth_provider.dart:246` | ✅ |
| مسح بعد نجاح التسجيل | `auth_provider.dart:310` | ✅ |
| الاستئناف بعد إغلاق التطبيق | `main.dart:443-448` | ✅ |

### 6.2 الناقص

- ❌ **لا عدّاد مرئي** — المستخدم لا يعرف أن أمامه 30 دقيقة
- ❌ **لا فحص قبل كل رفع** — الفحص عند الإرسال النهائي فقط
- ❌ **لا فحص عند العودة من الخلفية**
- ❌ **الانتهاء يظهر كاستثناء عربي مثبّت** عند الإرسال، بلا مسار استئناف واضح
- ❌ `cancelPendingDriverRegistration()` (`auth_provider.dart:430`) **معرّفة بلا مُستدعٍ** —
  لا يوجد زر «إلغاء التسجيل» في الواجهة

### 6.3 المطلوب إضافته

- [ ] **عدّاد مرئي** في خطوات الرفع عندما يتبقّى أقل من 5 دقائق
- [ ] **افحص `isExpired` قبل كل رفع** — إن انتهى، لا ترسل الطلب
- [ ] **افحص عند العودة من الخلفية** (`AppLifecycleState.resumed`)
- [ ] **مسار استئناف واضح:** عند الانتهاء أعد المستخدم لخطوة التحقق من الهاتف مع
      **الاحتفاظ بكل ما أدخله** (نوع المركبة، اللوحة، الموديل، والمستندات المرفوعة بنجاح
      — روابطها على الخادم تبقى صالحة)
- [ ] **اربط `cancelPendingDriverRegistration()` بزر إلغاء فعلي**
- [ ] **احذف الباسورد من السجل المحفوظ** (§1.4)

> **مهم:** المستندات المرفوعة بنجاح تُعيد روابط دائمة على الخادم. عند انتهاء التوكن **لا
> تفقدها** — احتفظ بها واطلب من المستخدم إعادة التحقق من الهاتف فقط.

## 8. ازدواج إدارة الحالة — قرار مطلوب

يوجد مساران متوازيان:

| | `providers/auth_provider.dart` | `bloc/auth/auth_bloc.dart` |
|---|---|---|
| النمط | `ChangeNotifier` + `provider` | `flutter_bloc` |
| الحجم | 732 سطر | 288 سطر |
| الاستخدام | **المسار الفعلي الذي تستدعيه الشاشات** | يحتاج تأكيداً |

**اختر واحداً واحذف الآخر.** `AuthProvider` هو الأنضج والأكثر استخداماً، لكن `Bloc` أفضل
لاختبار آلة الحالة. المهم ألّا يبقى الاثنان.

> تحقّق من استخدام `AuthBloc` الفعلي قبل الحذف: ابحث عن `BlocProvider<AuthBloc>` و
> `context.read<AuthBloc>()` في `screens/`.

## 9. سجل التعارضات بين التطبيق والخادم

| # | التعارض | التطبيق | الخادم | الإصلاح |
|---|---|---|---|---|
| 1 | قيم `deviceState` | `'trusted' \| 'new' \| 'revoked'` (`auth_service.dart:17`) | `'active' \| 'revoked' \| null` | وحّد على قيم الخادم — `'trusted'` و `'new'` **لا يُعادان أبداً** |
| 2 | كود الخطأ في الحظر | يقرأ `data['code']` | يُرسل `data['error']['code']` = `403` رقماً | أصلح الطرفين (§1.2) |
| 3 | معرّف المستخدم | `user['_id'] ?? user['id']` | `id` فقط | احذف `_id` |
| 4 | كتلة الجهاز في الدخول | لا تُرسل | يقبلها ويربطها | أرسلها |
| 5 | طول كود الـ OTP | 6 خانات في الواجهة | `verify-otp`: 6 · `driver/verify-phone`: **4–6** | وحّد على 6 |
| 6 | `isMockLocation` | يُرسل دائماً `false` | يُستقبل ويُتجاهل | احذفه أو فعّله |
| 7 | `expiresIn` | يُستخدم للعدّاد | ثابت `300` غير مشتق من Twilio | اشتقّه في الخادم |
| 8 | حد حجم الملف | **لا فحص إطلاقاً** — فقط `imageQuality: 85` و 1920px | يرفض > **10 MB** | افحص الحجم قبل الرفع |
| 9 | أنواع الملفات | نصّ الواجهة يقول «JPG, PNG, PDF (حد أقصى 5 MB)» | يقبل jpeg/png/**webp**/pdf حتى **10 MB** | صحّح النص — ثلاث معلومات خاطئة في سطر واحد |
| 10 | اختيار PDF | **مستحيل** — `ImagePicker.pickImage` فقط، ولا اعتماد على `file_picker` | يقبل `application/pdf` | أضف `file_picker` أو احذف PDF من النص |
| 11 | كتالوج أنواع المركبات | قائمة عربية **مثبّتة بستة أنواع** | `GET /vehicles/types` هو المصدر | استهلك الكتالوج فعلياً |
| 12 | `seats` | خريطة احتياطية محلية قد تتغلّب على قيمة الخادم | يشتقّها من `seatLayout` | دع الخادم يقرّر عند غياب القيمة |
| 13 | مفتاح الملف المرفوع (`key`) | يُهمَل | يُعاد مع `url` | احتفظ به للحذف لاحقاً |
| 14 | `state.isEditMode` | **`false` دائماً** فزر التعديل يقرأ «إكمال» | مسار `PATCH` موجود | أصلح العَلَم |
| 15 | تحقق الهاتف | ثلاث قواعد مختلفة، كلها للجزء المحلي | `^\+[1-9]\d{1,14}$` | دالة تطبيع واحدة (§1.6) |
| 16 | تفريع شاشة إعادة التعيين | تفحص **نصّ رسالة الخادم الإنجليزية** بعد `toLowerCase()` | الرسائل قابلة للتغيير والترجمة | فرّع على `errorCode` لا على النص |

> **البند 16 هش بشكل خاص:** أي تعديل في صياغة رسالة الخادم — أو ترجمتها — يكسر منطق
> الواجهة صامتاً. هذا بالضبط ما يحلّه كتالوج أكواد الأخطاء الـ 28 الذي يُسقطه الـ filter
> حالياً (خطة الخلفية §9b #2).

> **التعارض الأول له أثر عملي:** أي منطق واجهة يفحص `deviceState == 'trusted'` أو
> `== 'new'` **لن يتحقق أبداً**، لأن الخادم يُعيد `'active'`. تحقّق من الشاشات التي تفحص
> هذه القيمة.
